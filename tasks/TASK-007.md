# TASK-007 本地 Web 录入与结果演示界面（PI 可视版）

## 1. 目标（一句话，可验收）
把现有命令行能力搬到浏览器页面：PI 可在页面逐条填表或拖拽 CSV/JSON 录入，页面展示入库统计、去重、对比矩阵、校验汇总，并在页面内完成 L4 打分；后端复用现有 `src/literature` 纯函数，CLI 保留为调试入口。

## 2. 输入
- 现有模块：`ingest.py`、`dedup.py`、`matrix.py`、`verify.py`、`report.py`。
- 界面基线原型：`web/文献录入与验收演示原型.html`（视图：录入 / 看板 / 打分）。
- 样例：`src/samples/`、`golden-set/smoke/samples.csv`。

## 3. 输出
- `web/app.py`：Python 标准库 `http.server` 轻量服务（不引入 Flask/FastAPI）。
- `web/` 下单页前端（原生 JS，内联或同目录静态文件）：录入表单、拖拽导入、结果看板、内嵌打分。
- 接口路由复用现有函数；处理结果仍落 `data/`、`outputs/`，审计写 `audit/`。
- 打分结果回写 `audit/` 与 `registry.yaml` 对应任务卡状态。
- `tests/test_web.py`：页面接口与 CLI 同输入结果一致（L3 可复现）。

## 4. 约束（红线）
- 只允许改 `web/`、`src/literature/` 接入层、`tests/`；不改后端分层/去重规则。
- 零新增第三方依赖；外部联网校验仍按 TASK-005 开关，默认 mock。
- 不暴露命令行路径给 PI 界面；占位字段统一「待核实」，不编造。
- 真实数据脱敏；凭证只走环境变量。

## 5. 验收标准（四级）
- L1：页面字段齐全，表单/拖拽均可提交，错误在页面内提示。
- L2：页面展示的去重/矩阵/校验结果与脚本产物逐条一致。
- L3：同输入走页面与走 CLI，落盘结果一致（时间戳除外）。
- L4：非技术 PI 不看命令行，可独立完成一次录入、看懂结果并在页面打分 ≥4。

## 6. 派工与档位
- 执行：TRAE；审查：CodeBuddy（核对页面结果与脚本一致性）。
- 允许改目录：`web/`、`src/literature/`、`tests/`、`audit/`。
- **A 档**：页面排版、交互措辞；**B 档**：接口字段命名（留痕 decisions.md）。

## 7. token 预算
30k（单任务），超限暂停等确认。

## 8. 失败处理
- 服务起不来 → 回退静态原型演示，记 audit；不硬改后端规则。
- 页面与脚本结果不一致 → 以脚本产物为准，页面 bug 记入待修，不放宽验收。

## 9. 依赖
TASK-001~006 已待验收；本任务不等待 L4 打分即可开发界面。
